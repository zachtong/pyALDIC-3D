## 1. BLOCKER — figures

### 1a. Every figure is a placeholder

`figs/*.pdf` are grey placeholder boxes generated by
`repro/make_placeholder_figs.py` so the manuscript compiles and the layout can
be judged. **They must all be replaced before submission.**
`figs/README.md` is the production specification: for each figure it states the
message, exactly what the panels must show, the data source, and the script that
will make it. The generator refuses to overwrite a real figure (it checks a
`PLACEHOLDER` marker in the PDF metadata), so dropping a real
`figs/figN_*.pdf` into place and re-running is safe.

### 1b. The figure count exceeds the journal limit

SoftwareX caps an Original Software Publication at **six** figures; the draft
carries **eight** so the whole argument is visible. Planned merge, in priority
order (also recorded in `figs/README.md` and in a comment at the top of the
`.tex`):

1. Fold Fig. 3 (stereo geometry) into Fig. 1 (architecture) as an inset panel.
2. Fold Fig. 8 (scale/performance) into Fig. 7 (validation) as a bottom row, or
   move it to supplementary material.

Result: architecture+geometry, GUI, calibration, crack-aware, honesty gate,
validation(+performance) = **6**. Merging also removes ~130 words of caption,
which buys headroom under the word cap (§2).

## 3. Build the submission files

From `paper_softwareX/`:

```
python submission/make_submission_build.py
```

This creates `submission/build/`:

- `draft_softwareX_3D.pdf` — **the manuscript PDF to upload** (review marks
  hidden; the script aborts if any unresolved `\todo{}` marker is still present).
- `pyALDIC-3D_softwareX_latex_source.zip` — **the LaTeX source archive to
  upload** (clean `.tex`, `.bbl`, `reference.bib`, and the figure files under
  `figs/`).

It never edits the working copy; it hides `\jy{}` / `\zt{}` only in the build
copy. Requires `pdflatex` and `bibtex` on PATH. Open the built PDF and confirm
there is no coloured `[[JY:]]` / `[[ZT:]]` text anywhere before uploading.
